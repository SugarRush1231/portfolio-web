Problem

미디어 준비 작업에서는 파일 변환과 자막 생성, 번역을 반복하게 됩니다. 이 과정을 서로 다른 도구 사이에서 옮겨 다니지 않고 한 프로그램의 흐름으로 이어갈 수 있도록 MMT를 기획했습니다.

My role & AI collaboration

직접 맡은 역할

필요 기능과 동작 기준을 정하고, 사용자 관점에서 화면과 사용 절차를 점검했습니다. 오류 재확인과 수정 기준 설정, 배포 판단까지 맡았습니다.

AI와 협업한 범위

기능 구현, 오류 원인 분석, 검사 작성은 AI의 도움을 받아 진행했습니다. 생성된 결과를 그대로 채택하기보다 실제 프로그램에서 동작을 확인하고 다시 수정하는 과정을 반복했습니다.

Media workflow

변환 · 자막 · 번역

영상·오디오 변환과 Whisper 자막 생성, Gemma 번역을 연결했습니다. 영상 제작의 준비 작업을 한 흐름 안에서 다루도록 구성했습니다.

공통 모델 관리

기능마다 모델을 중복 설치하지 않고, 설치 상태와 실행 환경을 확인하게 했습니다. 모델이 없을 때 필요한 설치를 안내하고, 기존 모델은 자막·번역과 노래 자막 작업에서 재사용하도록 구성했습니다.

한 번의 클릭으로 영상 다운로드

위젯 모드는 흰 원형 다운로드 버튼으로 화면에 머무릅니다. 영상을 보고 있는 브라우저에서 버튼을 누르면 현재 영상 페이지를 감지해 다운로드를 시작합니다.

Issue → resolution

로그인 상태에서도 실패한 다운로드

로그인 여부만 원인으로 단정하지 않고, 오류가 발생한 주소 유형과 처리 경로를 구분했습니다. 주소를 단순 치환해 다른 영상을 받지 않도록 원본 주소와 콘텐츠 유형을 유지하는 기준을 세웠습니다.

수정 이후에도 사용자 재확인

주소 유형별 처리를 보강하고 콘텐츠 식별값과 유형 검증을 추가했습니다. 수정 뒤에는 신고한 사용자에게 실제 정상 작동 여부를 다시 확인해 대응을 마무리했습니다.

Usability & release

필요한 시점에 연결 안내

시작부터 브라우저 연결을 요구하는 대신, 로그인이 필요한 시점에 안내하도록 절차를 줄였습니다. UI 변경 뒤에는 기존 사용자의 실제 업데이트 동작도 확인했습니다.

확장 프로그램 공개 배포 대응

심사 자료와 개인정보 안내를 정리하고, 거절 사유 확인과 재제출에 대응했습니다. 브라우저 확장 0.2.15의 공개 게시까지 진행했습니다. 확장 프로그램과 데스크톱 앱은 별도로 버전을 관리합니다.

What this demonstrates

요구사항을 구체적인 동작 기준으로 바꾸고, AI 협업 결과를 실제 실행과 사용자 확인으로 검증하는 경험입니다. 구현에 그치지 않고 예외 상황, 사용성, 배포 이후의 피드백까지 이어서 다뤘습니다.
