# 가사 키네틱 타이포그래피 — 아트디렉션 v0.1

2026-10-21 작성. **MMT와 별개로 새로 만드는 독립 프로그램**에 적용할 첫 번째 연출 규격이다. 아래 수치는 이 프로젝트를 위한 디자인 결정이며, 보편적인 업계 표준이나 검증 완료 수치가 아니다. 아직 새 프로그램을 구현하거나 실제 음원을 렌더링하지 않았다.

## 1. 완성물의 방향

큰 활자, 분명한 위계, 통제된 화면 전환을 사용하는 음악 타이포 필름을 만든다. 읽는 순간과 움직이는 순간을 구분한다. 한 곡 전체에서 반복되는 시각적 문법을 유지하고, 음악의 전개에 따라 강도를 달리한다.

사용자가 음원과 가사를 제공하면 새 프로그램 안에서 싱크 분석부터 장면 구성과 영상 출력까지 처리한다. MMT의 설치·실행이나 사전 자막 생성을 요구하지 않는다. 사용자가 단어마다 위치와 효과를 고르도록 맡기지 않는다. 기본 결과는 영상으로 완성하고, 수정이 필요하면 해당 부분만 고칠 수 있게 한다.

## 2. 독립 프로그램의 범위

입력은 음원과 가사이고, 출력은 음악에 맞춰 배치·움직임·장면 전환이 적용된 타이포그래피 영상이다. 새 앱이 음원 분석, 가사 시간 정렬, 자동 연출, 미리보기와 영상 출력을 담당한다. 앱의 실행·배포는 MMT와 분리한다.

가사 싱크에 대한 기술 검토에서 MMT의 다음 구현을 확인했다:

- `AutomaticSubtitles/LyricsAlignmentService.cs`: 가사 줄별 시작·종료 시간 매칭.
- `AutomaticSubtitles/WhisperTimingTranscript.cs`: 토큰·단어 경계와 시간 처리.
- `AutomaticSubtitles/LyricsSubtitlePipeline.cs`: 줄별 SRT 저장.

이는 이미 보유한 기술의 참고 근거이며 새 앱의 실행 의존성이 아니다. 실제 구현을 재사용할지는 새 프로그램의 요구와 정확도를 검토한 뒤 정한다. MMT 소스 변경이나 두 앱의 결합을 전제로 하지 않는다.

새 앱은 원본 가사와 단어 시간의 연결 상태를 유지해야 한다. 줄별 SRT만으로 단어 하나하나의 정확한 등장 시간을 알 수는 없다. 단어 시간이 불확실한 구간은 줄별 연출로 처리하고, 줄 시간도 불확실하면 해당 구절을 확인 대상으로 표시한다.

## 3. 타이포와 화면 구성

첫 스타일은 한 서체와 한 색 체계로 완성한다. 곡마다 임의로 폰트·색을 바꾸지 않는다.

| 항목 | 규격 |
| --- | --- |
| 서체 | Pretendard. 일반 가사 700, 강조 900, 보조 500. 실제 글꼴 파일을 로컬에서 사용 |
| 1920×1080 기본 크기 | 일반 120px / 강조 192px / 보조 64px. 출력 크기에 비례해 환산 |
| 1080×1920 기본 크기 | 일반 112px / 강조 176px / 보조 60px. 가로형 장면을 축소하지 않고 재배치 |
| 행간 | 1.12em. 실제 한글·영문 잉크 영역이 겹치면 확대 |
| 자간 | 일반 -0.015em / 강조 -0.025em. 가로 비율 변형 금지, 글자 충돌 시 자간 보정 |
| 안전 영역 | 화면 좌우 8%, 위아래 9% 안쪽에 읽어야 하는 글자의 실제 외곽을 유지 |
| 기본 정렬 | 가사 블록 왼쪽 정렬. 강조 장면은 별도 중앙 축. 장면 안에서는 정렬 축 고정 |
| 줄바꿈 | 공백·구두점·기존 가사 구절을 우선. 한글 음절이나 결합 문자를 쪼개지 않음 |
| 길이 처리 | 구절 나누기 → 다음 줄 → 단계적 크기 축소 순서. 최소 보조 크기로도 안 맞으면 다음 장면으로 분할 |
| 기본 행수 | 2행 이내. 빠른 구간은 3행까지 허용하며 추가 장식 제거 |

출력 전에 실제 폰트의 글자 외곽과 이동 중 외곽을 모두 측정한다. 폰트가 없거나 다른 글꼴로 대체되면 출력 준비 실패로 처리한다. 영문만 강제 대문자로 바꾸거나 원래 가사의 구두점을 제거하지 않는다.

## 4. 색 체계

원시 색 → 역할 → 장면 요소의 순서로 연결한다. 구성 요소에서 임의 색을 추가하지 않는다.

| 원시 색 | 역할 | 적용 |
| --- | --- | --- |
| Ink `#141414` | 기본 배경 / 밝은 장면 글자 | 일반 장면 배경, 밝은 장면의 모든 가사 |
| Paper `#F2EEE7` | 기본 가사 / 밝은 장면 배경 | 기본 장면의 가사, 선택된 구간 경계의 반전 장면 |
| Vermilion `#FF653D` | 어두운 장면의 강조 | 한 구절의 강조 단어 최대 하나 |

밝은 장면에서는 강조색 대신 크기와 굵기를 사용한다. 색 반전은 구간 경계에서 한 번 적용하고 유지한다. 드럼이나 음량에 반응해 배경을 계속 점멸시키지 않는다. 그라데이션, 글로우, 외곽선, 그림자는 첫 스타일에서 사용하지 않는다.

## 5. 자동 장면 선택

세 가지 장면은 같은 시각 체계의 문법이다. 사용자에게 효과 목록으로 고르게 하지 않는다.

| 장면 | 선택 조건 | 화면에서 일어나는 일 |
| --- | --- | --- |
| Phrase | 기본값, 단어 시간이 불확실한 구간, 빠른 가사 | 구절을 하나의 읽기 단위로 등장시킨 뒤 위치 고정. 다음 구절로 이어짐 |
| Stack | 실제 단어 시간이 확보되고 2~3개의 짧은 읽기 단위로 나눌 수 있는 구절 | 같은 왼쪽 축을 따라 구절이 순서대로 쌓임. 새 단어를 넣을 공간은 미리 확보해 기존 글자가 밀리지 않음 |
| Hero | 길게 부르는 단어·구절 중 실제 화면 유지 시간 0.65초 이상이며 주변 가사와 충돌하지 않는 지점 | 강조 대상을 크게 펼치고 나머지 글자를 낮은 위계로 정리. 강세 순간의 짧은 충격 후 안정적으로 유지 |

Hero는 같은 구절에서 한 번, 이후 최소 8박 동안 재사용하지 않는다. 조건이 충족되지 않으면 Phrase로 내려간다. 단순히 음량이 크다는 이유로 의미상 중요한 단어라고 단정하지 않는다.

장면 선택 우선순위는 가사·시간 유효성 → 읽을 공간 → 읽을 시간 → 음악 강세 → 반복 구간의 일관성이다. 큰 효과를 넣으려고 가사 표시를 생략하지 않는다.

## 6. 타이밍과 움직임

가사의 등장 기준은 보컬 시간이다. 박자 검출 결과로 발음 시간을 덮어쓰지 않는다. 박자는 강조 동작과 구절 사이 전환을 배치하는 보조 정보다.

입장·정착은 `cubic-bezier(0.23, 1, 0.32, 1)`, 화면 내 재배치는 `cubic-bezier(0.77, 0, 0.175, 1)`을 기본으로 한다. 수치는 웹 UI 반응 시간이 아닌 영상의 박자와 읽기 시간을 기준으로 적용한다.

| 동작 | 기준 |
| --- | --- |
| 기본 입장 | 0.5박, 최소 120ms·최대 280ms. 글자 높이 0.12em의 이동과 불투명도 변화 후 정지 |
| 순차 입장 | 실제 단어 시작 시간 사용. 임의의 동일 간격으로 가사 발음을 대체하지 않음 |
| 강조 충격 | 강조 시점부터 1.00 → 1.035 → 1.00. 최대 0.5박·240ms 안에 정착. 글자 획은 왜곡하지 않음 |
| 장면 전환 | 가사 구절 경계에서 0.5박, 최대 320ms. 새 장면이 기존 장면의 정렬 축이나 이동 방향을 이어받음 |
| 퇴장 | 구절 종료 뒤 다음 구절의 공간을 확보하며 마침. 마지막 단어를 읽는 동안 지우지 않음 |
| 카메라 | 일반 가사는 고정. Hero 장면에서만 구절 종료 이후 1.00 → 최대 1.08의 전진을 허용하고 다음 장면으로 연결 |

같은 단어에 회전·스케일·자간 변형·카메라 이동을 동시에 걸지 않는다. 읽는 동안 글자가 계속 떨리거나 떠다니는 모션은 사용하지 않는다. 카메라 연출과 단어 충격은 서로 다른 시간에 배치한다.

빠른 가사는 효과 지속 시간을 억지로 줄여 깜빡이게 하지 않는다. 여러 단어를 한 읽기 단위로 묶고 문장 단위로 전환한다. 긴 음은 긴 바운스를 반복하는 대신 안정된 타이포를 유지한다.

## 7. 곡 전체의 연출

- **벌스:** Phrase 중심, 안정된 정렬 축과 여백을 유지한다.
- **후렴:** 검증된 반복 가사와 음악 변화가 함께 있을 때 Stack·Hero 비율을 높인다. 반복 후렴은 동일한 대표 구도를 재사용해 시각적 훅을 만든다.
- **브리지·간주:** 보컬이 없으면 가사 잔상을 정리하고 여백을 준다. 음악 변화만으로 구간을 확신할 수 없으면 안정된 기본 연출을 유지한다.
- **마지막:** 마지막 가사를 충분히 유지한 뒤 마친다. 음원 앞에 강제 인트로를 붙이거나 후렴마다 같은 줌 효과를 자동 삽입하지 않는다.

정확한 구조 정보 없이 구간을 벌스·후렴이라고 확정하지 않는다. 첫 버전은 반복 가사와 음악 변화로 후보를 만들되, 신뢰하기 어려운 부분은 Phrase로 처리한다. 같은 입력과 스타일 버전은 같은 장면 선택을 재현한다.

## 8. 기본 완료 검사

| 검사 | 실패 시 처리 |
| --- | --- |
| 입력 가사와 결과 가사의 순서·내용 대조 | 누락·중복·순서 오류를 숨기지 않고 해당 구절을 표시 |
| 단어 시간 연결 확인 | 단어 연출을 끄고 줄별 연출 사용. 줄 시간도 없으면 해당 구절을 미완료로 표시 |
| 정지·이동 중 글자 외곽의 안전 영역 검사 | 글자 나누기·장면 재배치. 읽는 글자를 잘라 출력하지 않음 |
| 강조와 일반 가사의 시각적 충돌 | 강조를 줄이거나 Phrase로 전환 |
| 빠른 구간의 동작 과밀 | 단어별 효과를 구절 단위로 통합 |
| 렌더링 결과 | 음원 길이·해상도·프레임 수·오디오 존재 확인, 끝부분 잘림과 검은 프레임 점검 |

자동 검사를 통과한 것이 전문가의 미적 판단을 대체했다는 뜻은 아니다. 첫 스타일은 느린 곡·빠른 곡·한영 혼합 가사의 실제 구간을 렌더링하고, 가독성·싱크·음악의 흐름·정지 화면 완성도를 검토하며 수정한다. 검증한 수치와 수정 이유를 이 문서에 반영한다.

## 9. 사용자에게 남길 작업

음원·가사 제공과 생성 실행. 화면 위치·강조 단어·효과를 매번 지정하게 하지 않는다. 자동 완성 결과와 확인이 필요한 구절을 먼저 제공한다. 수정 화면은 예외를 고치는 수단이며 기본 제작 절차가 아니다.

## 10. 비용과 적용 범위

로컬 분석과 로컬 렌더링을 전제로 하며 필수 유료 API·클라우드 GPU·구독 서비스는 도입하지 않는다. 처리 시간과 필요한 메모리는 실제 PC로 측정해야 한다. 이 문서는 신규 독립 프로그램의 설계이며, 기존 포트폴리오 사이트와 MMT의 소스는 변경하지 않는다. 이 문서를 저장한 포트폴리오의 analysis 폴더는 설계 기록 위치이며 새 앱의 소스 위치로 정한 것이 아니다.

## 근거와 구분

- [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard): 한글·영문을 함께 다루는 가변 글꼴 후보. [OFL 1.1 라이선스](https://github.com/orioncactus/pretendard/blob/main/LICENSE)를 파일 배포 시 함께 유지한다.
- [librosa의 박자 검출 구현](https://github.com/librosa/librosa/blob/main/librosa/beat.py): 템포와 박자 위치 추정의 기술 참고다. 박자 검출이 연출 의도를 자동으로 이해한다는 근거는 아니다.
- MMT 가사 싱크는 현재 로컬 소스의 자료형과 저장 경로를 확인했다. 이 조사에서 음원으로 재실행하지 않았다.
- 배치·색·강조 빈도·모션 수치는 위 도구가 정해준 값이 아니라 이 스타일을 위해 설계한 기준이다.
