# portfolio-web

정적 HTML/CSS/JavaScript 포트폴리오입니다. `index.html`을 열거나 정적 호스팅으로 배포합니다.

## 입구와 두 갈래

한 `index.html`이 주소에 따라 세 화면을 보여 줍니다. Netlify `_redirects`가 `/video`, `/software`를 `index.html`로 200 rewrite하고, `<head>` 맨 앞의 `site-mode` 스크립트가 주소를 보고 `<html data-mode>`를 정합니다.

| 주소 | 화면 |
| --- | --- |
| `/` | 입구: 이름과 두 갈래 링크 |
| `/video` | 영상 프로젝트 5개 |
| `/software` | 프로그램 프로젝트(MMT, Social Scene) |

- 옛 주소는 새로고침 없이 이어집니다: `/#project-mmt`, `/#project-social-scene` → `/software#...`, 그 밖의 `/#...`(영상·About·Contact) → `/video#...`, `/#hero` → `/`.
- `site-mode.js`가 `script.js`보다 먼저 다른 갈래의 카드와 상세 글을 DOM에서 뺍니다. 새 프로그램 프로젝트(예: 엑셀 애드인)는 카드에 `data-kind="software"`, 상세 글에 `class="project software-project"`를 붙이면 `/software`에만 나옵니다.
- 로컬 확인: `node tools/serve.cjs` 실행 후 `http://localhost:8888/`, `/video`, `/software`를 엽니다. 파일을 직접 열면(`file://`) 주소 갈래가 동작하지 않습니다.
- 느린 회선 확인: `node tools/serve.cjs 8889 --mbps 20 --latency 40`처럼 속도·지연을 주면 영상 로딩 표시와 클릭부터 재생까지의 시간을 확인할 수 있습니다(캐시 끔).

## 화면 및 테마

- 상단 Light / Dark 버튼으로 테마를 전환합니다. 작은 화면에서는 아이콘으로 표시합니다.
- 첫 방문은 기기의 화면 모드를 따르고, 직접 선택하면 `portfolio-theme` 값으로 브라우저에 저장합니다. 저장소가 차단돼도 현재 방문의 테마 전환은 동작합니다.
- `theme.js`는 스타일시트보다 먼저 실행해 초기 테마를 적용합니다. 사이트 배경과 브라우저 테마 색상을 함께 바꿉니다.
- 타이포는 영상과 겹치지 않게 단색 배경에서 전개합니다. 타이포 면의 글자 형태를 창으로 사용하고, 뒤쪽 영상 면을 향해 CSS 3D 시점을 전진시킵니다.
- 작품 첫 클릭은 주소나 페이지를 바꾸지 않습니다. 같은 이미지가 확대되고, 작품별 타이포 전개 뒤 글자 내부로 카메라가 들어가는 움직임을 거쳐 같은 화면의 영상으로 연결됩니다.
- Chrome은 Google / Chrome 전체 제목을 큰 두 줄 타이포로 전개합니다. 공식 G 벡터는 첫 글자로 사용하고 공개 Google Sans 서체로 나머지 글자를 구성하며, G를 마스크로 다시 그리지 않고 원래 로고의 빈 안쪽으로 진입합니다. Sugar Rush는 단어를 번갈아 강조하는 밴드 타이틀 리듬, Fire on up M/V는 가느다란 점화선에서 글자 전체로 펼쳐지는 2단계 타이틀, CHANEL은 공식 워드마크의 절제된 등장, Initial D는 기존 레이싱 진입·제동을 옮겨 곡선 진입 후 오른쪽 쏠림·기울임·수평 정지로 구분합니다. 카메라 진입과 탐색 동작은 공통으로 유지합니다.
- Google·CHANEL은 임의의 폰트로 로고를 흉내 내지 않고 실제 벡터 윤곽을 사용합니다. CHANEL의 로고는 폰트 파일이 아닙니다. 출처와 Google Sans 라이선스는 `assets/brand/`에 보관합니다. Google Sans는 작은 로컬 WOFF2로 필요한 글자만 포함합니다.
- 작품별 배경·제목·강조색을 라이트/다크 한 쌍으로 정의합니다. 썸네일의 실제 색 관계와 Color Hunt의 [네이비·흰색·빨강](https://colorhunt.co/palettes/navy-white-red), [검정·주황](https://colorhunt.co/palettes/black-orange) 조합을 참고한 자체 팔레트입니다. 팔레트를 그대로 복사하거나 자동 추출한 색은 아닙니다.
- 클릭 시 원본 화질 영상을 미리 불러옵니다. 0.7초 이미지 확대, 1.3초 타이포 전개, 1.1초 카메라 이동 뒤 재생을 시도합니다. 네트워크나 브라우저 자동재생 정책에 따라 기존 플레이어의 로딩·다시 재생 안내를 표시합니다.
- 타이포 전개 중 휠은 작품을 닫지 않고 전환이 끝날 때까지 기다립니다. 영상이 나온 뒤 휠은 가로채지 않고 아래의 사용 프로그램·설명·제작 과정으로 자연스럽게 스크롤합니다. 목록에서는 휠로 가로 탐색합니다. 가로 드래그·좌우 이동 버튼·방향키도 지원합니다. All work·Escape·다른 화면으로 이동은 전환 타이머와 재생을 취소합니다. 탭 숨김은 작품과 재생 위치를 유지하며 영상만 일시정지합니다. 인트로 도중 숨기면 영상 화면을 준비해 두고, 돌아와 재생 버튼으로 시작합니다.
- 영상이 나오면 해당 작품의 프로그램·기여도·설명·제작 과정을 바로 아래에 표시합니다. Process & credits는 이 설명으로 스크롤합니다. All work를 누르면 설명을 접고 원래 플레이어를 원래 위치로 돌려놓습니다. 플레이어를 복제하지 않습니다.
- 타이포는 입력 방식 때문에 생략하지 않습니다. 작품을 직접 클릭하면 시스템 동작 줄이기 설정과 관계없이 요청한 시네마틱 전환을 재생합니다. 키보드로 열면 타이포를 정적으로 보여준 뒤 영상으로 연결합니다. 보조 영상 등 자동 모션은 시스템 설정을 따릅니다.
- 작품별 배경색은 다크·라이트 선택을 따릅니다. 첫 화면 스트립은 기존 썸네일을 세로 창에 맞게 자르며 실제 영상은 원래 비율과 화질을 유지합니다.

## 영상

- 메인 영상은 `video/web/project-01.mp4`부터 `project-05.mp4`까지의 웹용 파일을 사용합니다. 원본 파일은 `video/`에 보관합니다.
- `project-02`~`04`는 원본(15~20Mbps)을 웹용으로 다시 인코딩했습니다. 해상도(1920×1080)와 프레임률은 원본과 같습니다. H.264 High 2패스, 영상 7Mbps(최대 10Mbps), 키프레임 2초 간격, AAC 192kbps 48kHz 스테레오입니다. 용량은 844MB에서 316MB로 줄었습니다. 원본 대비 VMAF 96.5~97.6, SSIM 0.993~0.996이고, 25·50·75% 지점의 1:1 비교에서 눈에 띄는 차이는 없었습니다.
  ```
  ffmpeg -i <원본> -c:v libx264 -preset slow -profile:v high -level 4.1 -pix_fmt yuv420p -b:v 7000k -maxrate 10000k -bufsize 14000k -g <fps×2> -keyint_min <fps×2> -sc_threshold 0 -pass 1|2 -c:a aac -b:a 192k -ar 48000 -ac 2 -movflags +faststart project-0N.mp4
  ```
- `project-01`(7.4Mbps)과 `05`(5.0Mbps)는 이미 목표 범위 이하라 다시 인코딩하지 않았습니다. 원본 스트림을 그대로 복사한 파일입니다(`ffmpeg -c copy -movflags +faststart`). 다시 압축하면 용량은 거의 그대로이고 화질만 떨어집니다.
- 다시 인코딩한 영상의 주소에는 `?v=날짜`를 붙여 브라우저가 예전 파일을 쓰지 않게 했습니다. 영상을 다시 바꾸면 이 값도 바꿉니다.
- MP4 재생 정보는 파일 앞에 배치했습니다(`faststart`). 파일 전체 다운로드를 기다리지 않고 재생을 시작할 수 있습니다.
- 아직 보이지 않은 보조 영상과 재생 전 메인 영상은 썸네일만 표시합니다. 상세 화면의 메인 영상은 재생 버튼을 누르면 주소를 연결하며, 첫 화면에서는 작품 클릭 시 연결해 전환 중에 미리 불러옵니다. 보조 영상은 화면에 25% 이상 보일 때 처음 로드해 무음 반복 재생하고, 화면 밖으로 나가거나 다른 탭·라이트박스를 열면 일시정지합니다. 다시 보이면 이어서 재생합니다. 클릭하면 라이트박스에서 크게 볼 수 있습니다.
- 기본 재생 볼륨은 50%입니다. 보조 영상은 기존과 같이 음소거 상태로 열리며, 음소거를 해제하면 50% 볼륨을 사용합니다.
- 기기의 동작 줄이기 설정이 켜져 있으면 보조 영상 자동재생을 멈춥니다.
- 작품 카드와 메인 영상 포스터는 `Thumbnail/work-01.jpg`부터 `work-05.jpg`까지의 경량 이미지입니다. 기존 썸네일의 구성을 유지한 경량 복사본이며 영상 화질과는 별개입니다.
- `video/web/` 폴더와 보조 WebM 영상, 썸네일도 함께 배포해야 합니다. 호스팅 서버의 HTTP Range 지원 여부에 따라 탐색과 버퍼링 성능이 달라집니다.

검증: `node --test tests/*.test.cjs`

## MMT UI 미리보기

MMT 상세 화면의 스크린샷을 `assets/mmt/preview/`의 HTML/CSS/JavaScript UI로 교체했습니다. `E:\Multi_Media_Toolkit - test\MMT.WinUI`의 `MainWindow.xaml`, `App.xaml`, 각 작업 페이지 XAML을 기준으로 메뉴, 문구, 옵션, 색상과 간격을 옮겼습니다. 앱 아이콘과 UI 아이콘은 원본 자산을 사용하고, 브랜드 서체는 필요한 글자만 포함합니다.

- 여섯 작업 메뉴와 설정을 전환하고 언어·모델·출력 포맷 등을 선택할 수 있습니다. 화면을 바꿔도 선택값과 입력 내용은 현재 방문 동안 유지됩니다.
- 파일 선택은 예시 파일만 표시합니다. 실제 로컬 파일, 로그인 정보, 네이티브 앱 또는 처리 서버에 연결하지 않습니다. 생성·변환·삭제 등 실제 작업은 실행하지 않으며, 클릭마다 안내 팝업을 띄우지 않습니다. 제한과 실제 앱과의 차이는 미리보기 아래에 한 번 안내합니다.
- 위젯은 `Assets/MMT_down.png`의 실제 다운로드 아이콘을 사용한 흰 원형 버튼입니다. 주변 배경·패널은 없고, 토글 또는 Escape로 닫습니다. 실제 앱에서는 현재 브라우저의 영상 페이지를 감지해 다운로드합니다.
- 메인 카드의 `assets/mmt/thumbnail-project.svg`는 원본 `MMT.ico`에서 추출한 아이콘과 프로젝트명만으로 구성했습니다. 아이콘을 새로 생성하거나 바꾸지 않았으며, 광고 문구·기능 나열·다운로드 CTA는 넣지 않습니다. 아이콘과 제목은 카드의 중앙 크롭 범위 안에 둡니다.
- iframe으로 스타일과 키보드 이벤트를 분리했습니다. 포트폴리오의 다크/라이트 테마와 관계없이 원본 MMT의 밝은 UI를 유지합니다. CSP로 네트워크 요청과 폼 제출을 차단하며, 사이트의 간편 저장 제한도 미리보기 안에 적용합니다.
- 정적 호스팅과 `index.html` 직접 열기를 모두 지원합니다. `assets/mmt/preview/` 전체를 함께 배포해야 합니다.
- `mmt-release.js`는 GitHub의 최신 정식 릴리스를 조회해 상단 다운로드 주소와 버전, 미리보기의 제목 표시줄·설정 버전을 함께 갱신합니다. `v숫자.숫자.숫자` 태그와 해당 저장소의 `MMT_Setup_버전.exe` 자산이 일치할 때만 적용합니다. 탭으로 돌아왔을 때 10분 간격으로 다시 확인하며, 요청 실패·제한 시 기본 설치 파일(v1.4.0) 링크를 유지합니다. 화면에는 설치 파일 다운로드 버튼만 표시하고 GitHub 릴리스 페이지 링크는 넣지 않습니다. 공개 메타데이터 조회 외에 설치 파일을 미리 내려받거나 실행하지 않습니다.

## Social Scene 통합 편집기

메인 카드의 Social Scene을 누르면 같은 포트폴리오의 `#project-social-scene` 상세 화면에서 템플릿을 편집하고 저장할 수 있습니다. 상세 안에서 시작하며, 사용자가 원할 때만 ‘별도 창으로 크게 보기’로 편집기만 엽니다.

- `assets/social-scene/app/`에 편집기와 폰트, 아이콘, 출력용 라이브러리를 함께 배포합니다. 메인에서는 편집기를 요청하지 않고 상세 화면을 처음 열 때만 불러옵니다. 무거운 MOV 변환기·WASM은 MOV 내보내기를 눌렀을 때만 로드합니다.
- 템플릿 24개와 내용·미디어·모션·키프레임 편집, 프로젝트 JSON, PNG, MP4, 투명 MOV 출력을 그대로 사용합니다. iframe의 `allow-downloads`로 사용자가 요청한 저장을 허용합니다.
- 출력은 상단 ‘저장’ 메뉴에서 형식을 누르면 시작합니다. 일반 화면은 현재 프레임 PNG·MP4를 지원합니다. 투명 대화와 Discord 발화자는 PNG·투명 MOV(권장)·투명 PNG 시퀀스 ZIP·MP4 순으로 표시합니다. 별도의 ‘동영상 출력’ 선택란은 숨기고 기존 프로젝트의 형식 값과 저장 엔진은 유지합니다. 프로젝트 JSON 저장은 별도 버튼으로 제공합니다. 메뉴는 방향키·Home·End·Escape와 바깥 클릭으로 조작하며, 저장 중에는 중복 실행을 막습니다.
- 카카오톡 투명 대화의 체크무늬는 미리보기에서만 보입니다. MP4는 마젠타 배경을 넣어 크로마키 합성용으로 저장하고, MOV와 PNG 시퀀스는 알파 채널을 사용합니다. 저장 메뉴에는 MP4 키잉 후 경계에 색 테두리가 남을 수 있다는 점과 투명 MOV 권장을 안내합니다.
- About·Contact·다른 프로젝트로 이동해도 편집 내용은 유지하고 미리보기 재생만 멈춥니다. 작업은 이 브라우저의 IndexedDB에 자동 복구본으로 저장합니다. 같은 탭의 새로고침에서는 모든 템플릿·미디어·현재 시간·편집 탭을 복구합니다. 브라우저 저장이 차단되거나 실패하면 안내를 표시합니다. 자동 복구와 별도로 중요한 작업은 프로젝트 JSON으로 보관하세요.
- 별도 창은 현재 템플릿·나머지 템플릿의 수정 내용·미디어·현재 시간·선택한 편집 탭을 이어받습니다. 별도 창을 닫거나 ‘여기서 계속 편집’을 누르면 원래 상세 화면으로 내용을 돌려보냅니다. 별도 창 사용 중에는 원래 편집 화면을 가리고 같은 크기의 영역에 안내와 복귀 버튼을 표시합니다. iframe은 제거하지 않고 입력을 막으며 재생을 멈춥니다. 원래 페이지를 새로고침해도 세션에 보관한 토큰으로 열려 있는 별도 창에 다시 연결합니다. 새로고침과 창 닫기가 겹치는 경우에도 브라우저의 복구본에서 이어갑니다.
- `social-scene-project.js`와 `assets/social-scene/embed.js`는 부모·자식 창과 같은 출처를 확인한 뒤 테마·활성 상태·진행 안내·편집 스냅샷을 주고받습니다. 새로고침 뒤의 별도 창 재연결은 해당 탭의 세션 토큰까지 일치할 때만 허용합니다. 포트폴리오의 테마는 편집 도구에 적용하고, 템플릿 내부 앱 화면의 테마 선택은 유지합니다.
- 폰에서는 열기·저장 버튼을 두 줄로 배치하고 템플릿, 미리보기, 타임라인, 편집 설정을 세로로 배치합니다. 320~1440px의 가로 넘침과 터치 입력, 전체화면 전환을 검사했습니다. 실제 iPhone·Galaxy의 키보드와 대용량 출력 성능은 별도 기기 검증이 필요합니다.
- 메뉴의 웹 서비스는 제공 서비스별로 묶습니다. NAVER에는 통합검색·뉴스 기사, Google에는 검색·AI 개요·AI 모드·Gmail을 둡니다. 메뉴 위치만 옮기고 프로젝트 ID와 실제 렌더링 분류는 유지합니다.
- 폰 설정에서 Galaxy의 하단 탐색을 제스처 바·3버튼·표시 안 함으로 선택하고, iPhone의 제스처 바를 표시하거나 숨길 수 있습니다. 두 기기의 선택은 독립적으로 저장하며, 기존 프로젝트는 제스처 바 표시를 유지합니다. 앱 자체의 하단 메뉴는 바뀌지 않습니다.
- PNG·MP4 등은 브라우저에서 처리합니다. 투명 MOV는 포함된 FFmpeg WASM으로 ProRes 4444 알파 채널을 만듭니다. MOV 변환에는 웹 주소와 Worker·WASM 로드를 허용하는 정적 호스팅이 필요합니다. `file://`에서는 실행 안내를 표시합니다. 별도 변환 서버나 유료 API는 사용하지 않습니다.
- Discord 발화자 화면의 출력 형식에서 ‘투명 MOV · ProRes 4444’를 선택할 수 있습니다. 발화자 테두리의 시간별 변화를 포함해 30fps·무음으로 저장합니다. 미리보기의 배경 선택을 유지하면서 출력에만 투명 배경을 적용합니다. 기존 투명 PNG 시퀀스와 배경 포함 MP4도 유지합니다.
- 내보내기 진행창의 취소·닫기 버튼은 라이트·다크 테마 모두 읽을 수 있는 색상과 44px 이상의 높이를 사용합니다. 진행률, 취소와 오류 안내를 유지하며 키보드 포커스도 표시합니다.
- `index.html`을 `file://`로 직접 열어도 편집기 표시와 일반 이미지·영상 저장, 별도 창 열기를 지원합니다. 파일 출처의 메시지는 지정된 편집기 창에서 온 경우만 받습니다. 준비 신호가 30초 동안 없으면 무한 로딩 대신 다시 불러오기 버튼을 표시합니다.
- 화면 직접 편집·입력칸·메시지 작성 중에는 Space가 재생 단축키로 처리되지 않습니다. 복사 시 타임라인의 입력 판별을 보정해 `plaintext-only` 편집 영역도 포함합니다. 라이트·다크 메뉴 아이콘의 배경과 글자·선 색상을 함께 지정하고 hover의 글자 대비도 유지합니다.
- `vendor/ffmpeg/ffmpeg-core.wasm`을 포함해 전체 폴더를 업로드해야 합니다. 서버는 `.js`, `.wasm`을 각각 JavaScript와 `application/wasm`으로 제공해야 합니다. 큰 MOV는 브라우저 메모리와 변환 시간이 필요하며 원래 편집기의 길이·메모리 제한을 유지합니다.

하단 탐색 검증은 템플릿·기기·탐색 방식 조합과 PNG·MP4의 실제 출력 픽셀을 확인합니다. Discord MOV 검증은 실제 ProRes 4444 파일의 알파 채널, 발화자 전환, 프레임 수와 무음 출력을 검사합니다. 진행창의 두 테마 대비, hover·포커스, 실제 시퀀스 출력 취소, 파일 직접 열기의 MOV 안내도 확인합니다. Premiere Pro에서 가져오기와 실제 휴대전화의 출력 성능은 이 자동 검사에 포함하지 않습니다.

## 상태 전환 점검

- Ctrl·Shift 등으로 메뉴를 다른 탭이나 창에 열어도 원래 작품을 닫지 않습니다.
- Ctrl+휠 확대와 브라우저의 수정키 방향키 단축키를 카드 탐색이 가로채지 않습니다.
- 늦게 완료된 영상 사전 재생 요청은 이미 시작한 재생이나 다시 연 작품의 시간을 바꾸지 않습니다.
- 연락처 복사는 실제 성공 여부에 따라 안내하며, 대체 복사가 실패해도 임시 입력창을 제거하고 원래 포커스를 복원합니다.
- 연도 갱신은 연도 표시에만 적용하며 사이트 소개 메타데이터를 덮어쓰지 않습니다.

- 바코드와 상세 화면의 이전·다음 화살표는 메인 `.work-preview` 카드 순서에서 자동 생성합니다. 새 프로젝트는 카드의 링크와 대응하는 상세 영역을 추가하면 탐색에도 반영됩니다. MMT 상세 화면의 바코드도 해당 작품의 타이포·재생 흐름으로 연결합니다.

- 페이지 전체 우클릭 메뉴와 Ctrl+S·Cmd+S 저장 단축키, 미디어 드래그 저장을 제한하고, 지원되는 브라우저의 기본 영상 다운로드 버튼을 숨깁니다. 재생·확대 보기·연락처 복사는 유지합니다. 이는 간편 저장 억제이며 브라우저 상단 메뉴의 페이지 저장·원본 주소 접근·개발자 도구·화면 녹화를 막는 DRM은 아닙니다.

- 마우스·터치 드래그로 작품을 넘기는 동작은 메인 카드 목록에서만 작동합니다. 타이포·카메라 전환·영상 재생·상세 화면에서는 갤러리 드래그를 시작하지 않으며, 작품을 열면 진행 중인 드래그 상태도 취소합니다.
